# LLM Wiki Web

**把文档整理成可阅读、可编辑、可追溯的 Markdown 知识库。**

LLM Wiki Web 是一个可自行部署的知识库工作台。上传文档后，系统提取正文、生成来源页与主题页，并通过链接组织材料。你可以在浏览器中编辑 Wiki、检索资料、向模型提问，或将研究结果保存为知识笔记。

知识库数据保存在本地文件系统中。基础检索和离线摘要无需模型服务；配置模型后，可以使用模型分析和问答能力。

## 功能概览

| 功能 | 说明 |
| --- | --- |
| 多知识库 | 按项目管理资料、Wiki、模型配置和会话 |
| 文档导入 | 上传单文件或 ZIP，支持分片上传、暂停和取消 |
| 正文转换 | 将支持的 Office、PDF 和文本资料转换为 Markdown |
| Wiki 整理 | 生成来源、概念、实体页面，以及索引和总览 |
| 编辑与预览 | Markdown 工具栏、分栏预览、表格、代码和数学公式 |
| 知识库问答 | 内置文件检索、来源引用、会话上下文和附件 |
| 深度研究 | 围绕问题检索资料，将结果保存为研究笔记 |
| 外部搜索 | 连接 Typesense 等服务，补充已有外部网页资料 |
| 图谱与体检 | 查看页面关系，检查断链、孤立页和元数据问题 |
| 扩展能力 | 配置 Skill 指令、MCP 服务及浏览器网页剪藏 |

典型工作流程：

```text
上传资料 → 提取正文 → 生成来源与主题页 → 检索 / 问答 / 研究
                         ↓                    ↓
                    Markdown 编辑         保存研究笔记
```

### 支持的文件

- **文本**：Markdown、TXT、HTML、CSV、TSV、JSON。
- **Office**：DOC、DOCX、PPT、PPTX、XLS、XLSX。
- **PDF**：提取可读取的文本，并尝试提取图片。
- **图片**：PNG、JPEG、WebP、GIF、BMP、TIFF 等，可导入并预览；当前没有通用 OCR 流程。
- **压缩包**：ZIP，后台解包并登记其中支持的文件。

DOCX、PPTX、XLSX 有内置解析。旧版 Office 和 PDF 转换依赖外部工具，Docker 镜像已包含 LibreOffice、Pandoc、Poppler 和中文字体。扫描版 PDF 如无文本层，需要先通过其他工具进行 OCR。

## 快速开始

先下载或克隆本仓库，进入包含 `package.json` 和 `docker-compose.yml` 的项目根目录。

### 方式一：Docker Compose

准备好 Docker 和 Docker Compose 后执行：

```bash
docker compose up -d --build
```

打开 **http://localhost:19827**。部署在服务器上时，将 `localhost` 替换为服务器地址。

默认端口映射为 `19827:3000`，数据持久化到宿主机的 `./data`。首次构建会下载依赖和文档转换工具。

常用管理命令：

```bash
# 查看运行状态
docker compose ps

# 查看日志
docker compose logs -f --tail=100 llm-wiki-web

# 停止服务
docker compose stop

# 更新代码后重新构建并启动
docker compose up -d --build
```

如需登录验证，在 `docker-compose.yml` 的 `environment` 中启用并设置 `LLM_WIKI_API_TOKEN`，重建容器后在网页输入相同 Token。对外部署时使用 HTTPS，并妥善保存 Token 和数据目录中的服务密钥。

### 方式二：本地运行

Node.js 版本要求见 [package.json](package.json)：支持 `20.19.x` 及以上的 20.x、`22.12.x` 及以上的 22.x，或 24 及以上；可使用 Node.js 22.12+ 的 22.x 版本。

开发模式：

```bash
npm ci
npm run dev
```

打开 **http://localhost:5173**。前端开发服务器将 API 请求转发至 `http://localhost:3000`。

生产模式：

```bash
npm ci
npm run build
npm start
```

打开 **http://localhost:3000**。本地运行时，需要自行安装并将所需的文档转换工具加入 `PATH`；缺少工具时，可先使用文本或支持内置解析的文件。

## 使用教程

### 1. 创建知识库

点击左侧 **新建**，填写名称及用途。不同知识库分别保存资料、设置和会话。知识库 ID 显示在左侧，可用于剪藏扩展或 API。

### 2. 上传资料

进入 **文件 → 上传**，选择文件或 ZIP。

上传、ZIP 解包和摄入是不同阶段：上传完成不代表知识库已经处理完毕。查看摄入队列，等待来源状态变为可用；失败时查看该文件的错误说明。

大量文件可先打包为 ZIP。上传期间只更新上传进度，整批结束后统一刷新文件列表。服务端默认分片大小为 8 MB。

### 3. 查看正文和 Wiki

在文件列表中打开来源页或转换全文，确认内容完整。点击左侧主题页查看相关原文及来源链接，也可以进入 **Wiki** 编辑 Markdown 并保存。

自动生成的主题说明用于组织来源内容；模型分析失败时会使用离线正文提取，并在来源中提示。重要结论可沿来源链接核对原文。

### 4. 配置模型并保存

进入 **设置 → 模型卡片**，添加服务地址和模型，完成获取与测试后点击 **保存设置**。具体步骤见下一节。

### 5. 提问和研究

进入 **查询**，选择模型或摘要模式，输入问题。可按需启用上下文、添加附件或开启外部搜索。需要整理多个来源时，可以使用深研功能并保存研究结果。

摘要模式提供离线检索和抽取式回答。模型模式会把选中的资料片段发送给配置的模型服务；启用外部搜索时也会向搜索服务发送查询。

### 6. 检查知识库

使用 **图谱** 查看页面间关系，使用 **体检** 检查断链、孤立页和来源缺失等问题。大库的图谱和体检存在数量限制，可通过配置调整。

## 模型配置

支持 OpenAI、OpenAI 兼容服务、Ollama、Anthropic、Gemini、火山方舟及 Coding Plan。

1. 进入 **设置 → 添加模型**，选择提供商。
2. 填写 Base URL、必要的 API Key，并启用卡片。
3. 点击 **获取模型**，选择服务实际提供的模型；也可以手动填写模型名称。
4. 点击 **测试模型**，检查实际短回答和耗时。
5. 设置默认模型并点击 **保存设置**，再到查询页选择它。

| 服务类型 | Base URL 示例 | 模型名称 |
| --- | --- | --- |
| OpenAI | `https://api.openai.com/v1` | 使用服务中可用的模型 ID |
| Ollama 原生接口 | `http://localhost:11434` | 使用本机已安装的模型名称 |
| OpenAI 兼容接口 | `http://localhost:8000/v1` | 使用服务暴露的模型 ID |

上表的本地地址适用于应用后端能直接访问该服务的情况。**Docker 中的 `localhost` 指向应用容器自身**；连接其他容器时使用同一网络中的服务名，连接宿主机服务时使用容器可达的宿主机地址。

测试和获取使用当前填写的配置，**不会自动保存**。测试通过仅表示短回答请求成功；长问答仍受模型速度、排队、上下文和代理超时影响。

Ollama 原生正式问答默认允许总计 600 秒、连续 120 秒无数据；服务端流式接收模型结果，网页在请求结束后显示回答。提前中断的回答会标明未完成。

## 外部搜索

**知识库检索始终使用内置搜索，无需安装 Typesense 或向量数据库。** Typesense 用于检索外部服务中已经建立的网页索引。

### 连接 Typesense

1. 在 **设置 → 外部搜索** 选择 Typesense。
2. 填写后端可访问的服务地址及 API Key。
3. 点击 **获取集合和字段**，选择保存网页资料的集合。
4. 检查检索字段，通常为已有的 `title`、`content` 等文字字段。
5. 点击 **测试搜索**，通过后保存设置。
6. 在查询或研究中开启外部搜索。

| 设置项 | 含义 | 如何取得 |
| --- | --- | --- |
| 网页索引集合 | Typesense 中存储网页记录的 collection | 通过获取按钮列出，或由索引维护者提供集合名 |
| 检索字段 | 用于匹配问题的文字字段 | 选择集合后自动读取，或按实际 schema 手填，多个字段以逗号分隔 |

获取集合和字段需要相应读取权限。仅检索密钥可配合手动填写集合及字段使用。网页记录需包含正文，以及 `url`、`link` 或 `canonical_url` 中的有效网页地址。

Typesense 本身不抓取互联网。只有空的 Typesense 服务时，需要先通过自己的采集或导入流程建立网页索引。本应用不会把知识库资料写入该外部集合。

## Skill、MCP 与网页剪藏

### Skill 与 MCP

在设置页添加 Skill，可保存回答格式、术语约定等指令；启用并保存后用于查询。

MCP 支持 HTTP、SSE 和 stdio。配置后可测试连接、获取工具和资源。查询可调用满足应用规则的只读检索工具，其他工具作为能力目录提供给模型。stdio 命令运行在应用后端的主机或容器中，相关程序必须安装在该环境。

### 浏览器扩展

1. 打开 Chrome/Chromium 扩展管理页并启用开发者模式。
2. 选择“加载已解压的扩展程序”，加载仓库的 [extension](extension/) 目录。
3. 填写服务地址、知识库 ID；启用登录验证时还需填写 API Token。
4. 在需要保存的网页上点击 **发送当前页面**。
5. 回到文件页查看摄入进度。

## 配置与数据

模型、搜索及能力配置优先在网页设置页管理。运行参数参考 [.env.example](.env.example) 和 [docker-compose.yml](docker-compose.yml)。

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `PORT` | `3000` | 后端监听端口 |
| `LLM_WIKI_DATA_DIR` | `./data` | 本地数据目录；容器中为 `/data` |
| `LLM_WIKI_API_TOKEN` | 未设置 | 网页及 API 访问验证 |
| `LLM_WIKI_UPLOAD_CHUNK_MB` | `8` | 上传分片大小，MB |
| `LLM_WIKI_MAX_UPLOAD_SIZE_MB` | `10240` | 单个上传文件大小上限，MB |
| `LLM_WIKI_MODEL_TIMEOUT_MS` | `120000` | 模型测试及一般模型请求超时；Ollama 原生正式问答的空闲时限 |
| `LLM_WIKI_OLLAMA_CHAT_TIMEOUT_MS` | `600000` | Ollama 原生正式问答总时限 |
| `LLM_WIKI_ANALYSIS_TIMEOUT_MS` | `30000` | 摄入模型分析时限，默认不超过一般模型时限 |
| `LLM_WIKI_ANALYSIS_MAX_TOKENS` | `1024` | 摄入分析输出额度 |

应用后端不会自动加载 `.env`。本地可在启动终端设置环境变量；生产构建后，也可显式使用 `node --env-file=.env dist/server/index.js`。Docker 的运行参数应写入 Compose 的 `environment`；仅把未被 Compose 引用的变量加入 `.env` 不会传入容器。

数据结构：

```text
data/
├── projects.json                # 知识库列表
└── projects/<project-id>/
    ├── raw/                     # 原始资料和资源
    ├── wiki/
    │   ├── sources/converted/   # 转换全文
    │   ├── concepts/            # 概念页
    │   ├── entities/            # 实体页
    │   ├── queries/             # 保存的问答
    │   └── research/            # 研究笔记
    ├── .llm-wiki/               # 配置、来源登记和队列
    └── chats/                   # 会话记录
```

备份时停止服务，再备份完整的数据目录；恢复时保持目录结构和访问权限。配置可能包含 API Key，不要将运行数据或 `.env` 提交到公开仓库。

## 常见问题

### 上传完成后为什么还不能查询？

上传后还需要解包、转换和摄入。等待来源状态变为可用，并检查“转换全文”是否有正文。失败文件会显示错误说明。

### 大文件上传出现 413 或连接重置？

检查反向代理的请求体限制。默认分片为 8 MB，代理限制需要留出余量，例如 Nginx 可设置 `client_max_body_size 32m;`。长问答还需要相应配置代理读取超时。

### 模型测试通过，但问答失败？

先确认已保存设置、查询页选中了正确模型，再查看实际错误。短测试不能验证长上下文性能；检查模型排队情况、可用内存以及应用和代理的超时设置。

### 为什么部分文件使用离线摘要？

模型分析超时或返回无效结果时，系统改用正文规则提取。同一轮队列中相同配置的后续文件会跳过失败模型，避免重复等待。修改配置或启动下一轮队列会重新尝试。转换全文仍保留，可直接检索。

### 如何修复旧的空主题页？

更新代码、完成构建并停止应用服务后，在相同数据目录配置下运行以下命令，将 `YOUR_PROJECT_ID` 替换为实际知识库 ID：

```bash
npm run repair:topics -- --project YOUR_PROJECT_ID
```

Docker 部署：

```bash
docker compose build llm-wiki-web
docker compose stop llm-wiki-web
docker compose run --rm --no-deps llm-wiki-web npm run repair:topics -- --project YOUR_PROJECT_ID
docker compose up -d llm-wiki-web
```

命令从已有来源和转换正文补充占位定义、空笔记及来源信息，保留人工实质内容，不调用模型。重复运行不会重复追加；不要与摄入进程同时执行。

## 开发与验证

技术栈：React 19、TypeScript、Vite、Express 5、Markdown 文件存储；测试使用 Vitest 和 jsdom。

```bash
npm run typecheck     # 前后端类型检查
npm test              # 单元与界面回归
npm run build         # 生产构建
npm run test:smoke    # 构建后运行隔离 HTTP 冒烟
```

源码入口：

| 目录 | 内容 |
| --- | --- |
| `src/` | 前端界面、交互与样式 |
| `server/` | API、文档摄入、检索、模型及研究逻辑 |
| `tests/` | 回归测试和协议测试服务 |
| `scripts/` | 冒烟测试及辅助脚本 |
| `extension/` | 浏览器剪藏扩展 |

提交问题时，请附上复现步骤、部署方式、应用日志及预期结果，并移除密钥和私有资料。提交改动前运行与改动相关的测试及类型检查。
